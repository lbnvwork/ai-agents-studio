# toolkit — скрипты управления проектом

Живут в ядре; `setup.sh` разворачивает их копиями в `docs/09-Служебное/Скрипты/` каждого клона
вместе с конфигом `.agents` (локальный: `CORE=<ядро>`, `PROJECT=<профиль>`). Правки — только здесь.

## Состав

| Файл | Назначение |
|---|---|
| `project.py` | общий модуль: читает профиль (ядро или `--layer`), отдаёт агентов, дорожки, ёмкости, словарь `awaiting`, план, маршрутизацию |
| `scripts/sprint_plan.py` | план из данных: `--write` (витрины + AUTO-области), `--check` (полнота данных) |
| `scripts/kanban_sync.py` | карточки канбана из статусов: `--write` |
| `scripts/check_meta.py` | проверка frontmatter задач (включая значение `awaiting` по словарю профиля) |
| `scripts/comment_stamp.py` | метка записи в канал статьи (фактическое время МСК), `--write` |
| `scripts/check_comments.py` | проверка статьи: «Контекст передачи», каналы, бюджеты, формат записей |
| `scripts/comments_feed.py` | лента/дайджест событий по задачам |

## Как ищется профиль

1. `--core` / `--project` / `--layer`; 2) окружение `AGENTS_*`; 3) `.agents` рядом со скриптом;
4) автоопределение, если в `<ядро>/profiles` ровно один профиль. Дорожки, ёмкости, подписи агентов,
словарь `awaiting` и маршрутизация «тип задачи → дорожка» — данные профиля/слоя, не код.

## Обновление

`./setup.sh --project <проект>` → `./setup.sh --project <проект> --check` (дрейф копий в docs).
Оставить в работе одну команду в каждом каталоге — нельзя: правки затрутся при следующем `setup.sh`. Если команда из ядра настраивается под проект (стек, порты) — это отдельная задача.
