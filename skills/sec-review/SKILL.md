# sec-review — security-ревью PR

## Вход

- `S.NN` — код задачи (обязателен; нет — спроси).
- `BRANCH` — ветка; `PR` — номер PR, если есть (иначе дифф по ветке).
- Проект — по умолчанию `ibs`.

## 1. Контекст

```bash
ART=$(ls src/ibs-docs/03-Задачи/Спринты/*/S.NN.*.md 2>/dev/null | head -1); echo "$ART"
sed -n '1,90p' "$ART"
git -C src/ibs fetch -q origin
git -C src/ibs diff --name-only origin/develop...origin/$BRANCH
# если дан PR и gh настроен:
gh pr diff "$PR" --name-only
```

Читай статью (требования, сценарии, «Требования безопасности»), затем дифф по файлам.

## 2. Карта изменений

Разложи файлы: контроллеры/маршруты · voters/роли · сущности и миграции · конфиги и `.env` ·
внешние вызовы (HTTP, очереди, файлы) · загрузки · логи и события. Один пункт = один файл:строка.

## 3. Статика

Команды и пороги — из скилла `sec-tooling`. Минимум: секреты (`gitleaks`), SCA (`composer audit`,
`npm audit`), SAST (что настроено в проекте), SBOM. Инструмент не запускался — так и напиши:
`не запускалось, причина`.

## 4. Чек-лист (по каждому: ок / находка / не применимо)

Аутентификация · авторизация и **IDOR** (чужой id) · инъекции (SQL, команды, шаблоны) · XSS/CSRF ·
SSRF · секреты в коде/конфигах/истории · крипто (алгоритмы, ключи, RNG) · обработка ошибок без утечек ·
логи и ПДн · rate limit · миграции и права БД · зависимости и лицензии (`oss-license-check`).

## 5. Негативные ветки

Для найденных рисков проверь, есть ли тест. Нет — `стоит добавить <имя теста>` (сам код не пишешь).
Сверяй с покрытием (`check-coverage`), а не по памяти.

## 6. Вердикт

- **`соответствует`** — находок нет, доказательства приложены.
- **`есть замечания`** — medium/low, мерж возможен после исправления или принятого риска.
- **`блокер`** — critical/high: мерж и релиз запрещены.

Каждая находка: `severity · файл:строка · чем грозит · как исправить · основание (пункт)`.

## 7. Формат и куда записать

- Полный разбор — `<проект>/docs/Безопасность/Записи/<S.NN>-review-<ГГГГ-ММ-ДД>.md`.
- В PR — блок замечаний (по согласованию с ПМом), в чат ПМу — вердикт одной строкой + ссылка на запись.
- Статью и карточки не правишь; код не коммитишь.

## Статья и канал

- В статье задачи дополняй раздел `## Безопасность`: кратко (соответствует / замечания / блокер) + ссылка на `Безопасность/Записи/<S.NN>-review-<дата>.md`.
- Запись в канал (создастся сама):
  `cd src/ibs-docs && python3 09-Служебное/Скрипты/comment_stamp.py --project <проект> --who "Ной (безопасность)" --type вердикт --file "<статья>" --write "соответствует / замечания / блокер; запись — Безопасность/Записи/<S.NN>-review-<дата>.md"`
- Нет rw-клона проекта — отдай готовый блок ПМу; он вставит в раздел и канал.

## Границы

Не заменяешь тестирование (это `sec-verify`); не даёшь сертификат; не правишь чужой код;
реальные ПДн не копируешь; прод и боевая БД — только чтение.
