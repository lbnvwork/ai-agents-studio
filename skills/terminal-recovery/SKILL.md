# terminal-recovery — когда команды не запускаются

Проверено 24.09.26 (VS Code + Cline 4.1.20, Ubuntu, bash 5.2).

## 1. `spawn /usr/bin/bash ENOENT` — мёртвый cwd, а не сломанный терминал

Симптом: любой вызов команды падает с `Failed to execute command: spawn /usr/bin/bash ENOENT`,
а `search_codebase` отвечает «Searched 0 files». При этом `/usr/bin/bash` на месте.

Причина: Cline запускает команду с `cwd` = каталог **задачи** (workspaceFolder), а не процесса VS Code;
Node при `spawn` с несуществующим `cwd` отдаёт именно `ENOENT` — поэтому в тексте ошибки оказывается имя бинарника.
Типичный случай: каталог проекта переехал/переименован, а чат открыт старый.

**Что не помогает (не тратить время):** `Restart Extension Host`, перезапуск VS Code на старом пути,
переустановка bash. `cd <новый путь>` внутри команды — тоже: bash не стартует, `cd` не исполняется.

**Что помогает:**

1. Полностью перезапустить VS Code, открыв **новый** корень (`File → Open Folder…` через диалог, не Recent),
   и начать **новую** задачу — она получит валидный `workspaceFolder`.
2. Сохранить старый чат: вернуть старый адрес симлинком `ln -sfn <новый путь> <старый путь>`
   (если переехал весь корень проектов — шим из набора симлинков, см. стандарты студии).
3. Сверить в шапке задачи Cline «Environment / Working directory» с `pwd`: путь должен существовать.

Быстрая диагностика в терминале VS Code (он от Cline не зависит):

```bash
pwd; ls -d <путь из ошибки>; ls -1 ~/work
```

**Точный список мёртвых адресов** (какой `cwd` помнит каждая задача) — в базе Cline:

```bash
sqlite3 ~/.cline/data/db/sessions.db "select distinct cwd from sessions;" | while read -r p; do
  [ -d "$p" ] && echo "ЖИВ   $p" || echo "МЁРТВ $p"; done
```

`cwd` задачи менять нельзя (фиксируется при создании, в UI/настройках такого нет) — лечим адресом: `ln -sfn <новый путь> <старый путь>`.

## 2. Вывод команд склеивается / коды возврата врут

Причина: режим терминала Cline **не** «Background Exec». В режиме «VS Code Terminal» Cline ждёт маркер
завершения через shell integration; если маркер не доходит, включается `markerless_heuristic` (таймер):
результаты соседних команд склеиваются, вывод может принадлежать другой команде, `exit 1` появляется
на успешных командах, длинные команды читаются не до конца.

**Лечение:** Cline → Settings → Terminal → **Terminal Execution Mode = «Background Exec»**.

**Симптом сломанного режима:** «Shell integration did not report command completion … captured with a timing heuristic»
или вывод, не соответствующий отправленной команде.

**Что НЕ помогает:** настройки VS Code `terminal.integrated.*` (проверено: правка + `Developer: Reload Window`
+ kill всех терминалов — поведение не изменилось). Обновление расширения: 4.1.20 — последняя версия.

## 3. Канарейки (30 секунд)

```bash
echo "canary ok"                                             # должен вернуться своим выводом
sleep 8; echo "long ok"                                      # длинная команда — тоже
docker compose exec -T <сервис> sh -lc '<команда тестов>'    # реальная длинная (команды — в скилле run-tests)
```

Все три вернулись своими выводами — терминал в порядке. Вернулся «общий снимок» или warning — см. п. 2.
