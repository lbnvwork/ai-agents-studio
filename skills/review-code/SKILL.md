# Review-code

## Порядок
1. Подтяни `develop`; определи ветку/PR для ревью.
2. Прочитай диф (`gh pr diff <N>` / код ветки).
3. **Проверь тесты**: посмотри CI-статус PR (зелёный/красный); если CI нет — запусти сам (команды прогона — в скилле `run-tests`). НЕ доверяй заявленному покрытию.
4. **Security** — пройди регламент `docs/09-Служебное/Регламенты/Security-чеклист.md` (JWT/RBAC, IDOR, XSS, секреты, валидация).
5. **Разделяй** «системный пробел» (существует и вне этой задачи) от «пробела задачи».
6. **Мёртвый код** — пройди скилл `find-dead-code`: символы из дифа, которые используются **только тестами**, — это блокер (вернуть деву на удаление; тесты переписываются). Легальные исключения (DI-теги, команды/контроллеры/процессоры, ресурсы API, тест-дубли, публичный контракт по ТЗ) — принять осознанно и написать одну строку, почему.
7. **Вердикт явный**: готово к мержу / на доработку + список блокеров (по приоритету).

## Куда писать
- Замечания по коду → комментарии в **PR** (inline/суммарно).
- В задачу → **короткий статус**: вердикт + ссылка «замечания в PR #N» (+ краткий security-чек-лист). Не дублируй подробности в задачу.

## Чек-лист
- [ ] Тесты проверены (CI-статус или локальный прогон по скиллу `run-tests`); в PR заполнена секция «Тесты» — иначе вернуть деву
- [ ] **Мёртвый код проверен** (скилл `find-dead-code`): нет символов, используемых только тестами; исключения обоснованы
- [ ] Security-чек-лист пройден
- [ ] Блокеры отделены от рекомендаций
- [ ] Замечания в PR; в задаче — короткий статус
- [ ] Вердикт явный
