# rbpo-parse — локальная база материалов

## Что парсим

| Источник | Что берём | Куда |
|---|---|---|
| `https://pvs-studio.ru/ru/webinar/rbpo/` | список 30 вебинаров: № · процесс · дата · ссылка на запись | `docs/материалы/00-Вебинары.md` |
| `https://pvs-studio.ru/ru/webinar/rbpo/content/` | полный текст (~168 тыс. символов): введение, термины, разборы 25 процессов (5.1–5.25) | `docs/материалы/01-Введение.md`, `docs/материалы/процессы/05.NN-….md` |

Видео **не** скачиваем — только ссылки. Расшифровки (ASR) — отдельная задача, не в этом скилле.

## Запуск

```bash
cd docs
python3 парсер/fetch_rbpo.py --write     # скачать и пересобрать базу
python3 парсер/fetch_rbpo.py --check     # только проверить: изменились ли материалы на сайте
```

После `--write` посмотреть отчёт: сколько разделов, какие новые/удалённые, размер.

## Правила

- **Вежливость:** один запрос на страницу, пауза, никакой массовой закачки. Кэш исходного HTML — `материалы/_raw/`.
- **Манифест обязателен:** `материалы/MANIFEST.md` — URL · дата извлечения · sha256 · размер. Без него база не считается доказательством.
- **Материалы третьих лиц** (© PVS-Studio / УЦ «МАСКОМ»): только внутреннее использование, ссылка на источник сохраняется, наружу не выкладываем, в публичные отчёты цитаты не тащим.
- Страница может измениться (новая вёрстка) → парсер падает по числу разделов: проверять ожидаемые 25 процессов, а не «сколько получилось».
- Обновление базы оформляем записью: что изменилось и какие процессы затронуты (это вход для пересмотра политики).
