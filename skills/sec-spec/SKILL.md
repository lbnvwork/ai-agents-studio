# sec-spec — требования безопасности к задаче

## Вход

- `S.NN` — код задачи (обязателен; не указан — спроси, не угадывай).
- Проект — по умолчанию `ibs`.
- Больше ничего не нужно: статью, изменения и данные собираешь сам.

## 1. Контекст (до анализа)

```bash
ART=$(ls src/ibs-docs/03-Задачи/Спринты/*/S.NN.*.md 2>/dev/null | head -1); echo "$ART"
sed -n '1,90p' "$ART"
grep -n 'Требования\|Сценарии\|Бизнес-логика\|Что меняем\|Реализация' "$ART" | head -20
git -C src/ibs fetch -q origin && git -C src/ibs log --oneline -5 origin/develop
```

Читай: постановку, сценарии, бизнес-логику, «Контекст передачи», 5 последних записей каналов.
Код и доки — только read-only клоны, ничего не правишь.

## 2. Классификация изменений

Таблица «затрагивается / нет / не применимо»: аутентификация · авторизация и роли · ПДн и медданные ·
крипта · внешние интеграции · загрузка файлов · платежи · новые эндпоинты · изменения схемы БД · зависимости.

## 3. Требования (5–10, проверяемые)

Каждое: `требование → как проверить → доказательство → основание`.
Основания — **с номером пункта**: ГОСТ Р 56939-2024 (процессы 3 «требования безопасности» и
7 «моделирование угроз»), 152-ФЗ (если ПДн), приказ ФСТЭК № 240. Нет пункта — метка `толкование`.

## 4. Abuse cases (5–7)

`сценарий → шаги → ожидаемо → что проверяем в логах`. Только на тестовый контур, без реальных ПДн.

## 5. Гейты

Что включаем на этой задаче: security-ревью PR · DAST · сверка ПДн · модель угроз · проверка лицензий.
Если гейт не нужен — причина одной строкой.

## 6. Вопросы (только реальные)

Августу — право (152-ФЗ, приказ 240), куратору-врачу — клиника, DevOps — контур/стенд.
Формат: `вопрос → кому → почему блокирует`.

## 7. Формат ответа

- **Вердикт:** `требования готовы` / `нужны уточнения (список)`.
- Блок **«Требования безопасности»**, готовый к вставке в статью (ПМ вставит сам).
- Таблица классификации, abuse cases, гейты, вопросы, метки уровня у каждого утверждения.

## 8. Куда записать

`<проект>/docs/Безопасность/Записи/<S.NN>-spec-<ГГГГ-ММ-ДД>.md` — полный разбор.
ПМу — короткий блок в чат (статьи задач не правишь).

## Статья и канал

- В статье задачи дополняй раздел `## Безопасность`: кратко (требования готовы) + ссылка на `Безопасность/Записи/<S.NN>-spec-<дата>.md`.
- Запись в канал (создастся сама):
  `cd src/ibs-docs && python3 09-Служебное/Скрипты/comment_stamp.py --project <проект> --who "Ной (безопасность)" --type вердикт --file "<статья>" --write "требования готовы; запись — Безопасность/Записи/<S.NN>-spec-<дата>.md"`
- Нет rw-клона проекта — отдай готовый блок ПМу; он вставит в раздел и канал.

## Границы

Не правишь код, статьи и карточки; не даёшь заключений о сертификации; не обещаешь «соответствует ГОСТ»
без доказательств; коммиты делает руководитель (`sec doc …`).
