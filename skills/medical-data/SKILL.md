# medical-data — медицинские данные

## Что готовим

| Тип | Пример | Формат отдачи |
|---|---|---|
| Справочник препаратов и групп | варфарин, фенилин, ПОАК, антиагреганты | таблица: код · название · группа · ед. дозирования · источник |
| Справочник доз/шагов | стартовая, поддерживающая, шаг изменения, максимум | таблица с колонкой «источник (редакция, дата)» |
| Пороги и шкалы | целевые диапазоны, HAS-BLED, CHA₂DS₂-VASc, SCORE, TTR | таблица «параметр · значение · источник» |
| Обезличенные наборы | кейсы для демо и тестов (без ФИО/адресов/номеров) | CSV/JSON по согласованной схеме проекта |
| Справочники-классификаторы | МКБ, регионы, ЛПУ, лабораторные показатели | таблица + примечание о правах использования (в связке с юристом) |

## Порядок

1. **Согласовать схему** с ПМ/Аналитиком: какие поля нужны продукту (иначе данные «не те»).
2. **Собрать из источника** — каждая строка с указанием источника и даты; строки без источника не попадают в набор.
3. **Проверить полноту и дубли**: одна сущность — одна строка; конфликтующие значения — в список вопросов куратору.
4. **Обезличить** демо-кейсы: нет ФИО, телефонов, адресов, точных дат рождения; идентификаторы — синтетические.
5. **Отдать в проект в его формате** (фикстуры/seed/CSV) и приложить README: источник, дата, что исключено.

## Правила

- **Никаких ПДн**: ни в файлах, ни в отчётах, ни в чате.
- Числа — только из источника; «примерно» запрещено, лучше пропуск с пометкой `требует куратора`.
- Данные куратора **не переписываем молча**: расхождения фиксируем таблицей и выносим вопрос.
- Права на справочники (МКБ, инструкции, шкалы) — проверяет юрист; в README ссылка на его комплаенс.
- Демо-набор и «настоящие» данные не смешиваем: в проекте всегда видно, что это демо.
