# Git-workflow

- Ветка на задачу от `develop`: `S_NN_название`.
- Коммит: `<код> <тип> <описание>` (напр. `N.N doc new ...`).
- По завершении создай PR: `gh pr create --base develop --head <ветка> --title 'S.NN Название' --body-file <файл>`. Тело — по шаблону `docs/03-Задачи/_Шаблоны/PR.md`.
- Перед PR: прогон тестов + `git merge develop` в своей ветке.
- Не пушить напрямую в `develop`/`main`.

## Порядок при завершении задачи (обязательно)

1. **Код:**
   ```bash
   git fetch origin
   git pull origin develop                        # или: checkout develop → pull → checkout <ветка> → merge develop
   git checkout -b S_NN_название                  # если ветки нет — от актуального develop
    # тесты — скиллом run-tests (команды под стек проекта), обязательно
    # мёртвый код — скиллом find-dead-code (код, живущий только для тестов, удаляем)
   git push -u origin <ветка>                     # по отмашке
   ```
2. **Мёртвый код (перед PR, обязательно):** пройди скилл `find-dead-code` по **всем символам из дифа** — если символ используется только тестами, он удаляется (тесты переписываются), а не остаётся «для покрытия». Исключения (DI-теги, команды, ресурсы API, тест-дубли, публичный контракт по ТЗ) — зафиксировать одной строкой в отчёте/PR.
3. **Docs (`{{DOCS_REPO}}`):**
   ```bash
   git pull origin main
   # <правки> → git diff
   ```
4. **Отчёт:** по формату `20-workflow` — `СДЕЛАНО/ФАЙЛЫ/БЛОКЕРЫ/ЗАМЕТКИ` + отдельный блок **`КОММИТЫ`** (только строки названий `[код]`/`[docs]`, без служебных пометок) + служебная строка `СТАТУС` **вне** блока → руководителю отправляется только блок `КОММИТЫ`.

> Синхронизация — ответственность агента ДО отчёта. Не передавай коммит на устаревшей базе.
