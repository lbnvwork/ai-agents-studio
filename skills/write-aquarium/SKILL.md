# Аквариум — логика и движение данных

**Триггер:** «делай пулрек, пиши аквариум» (или «пиши аквариум»).
**Момент:** после всех коммитов в ветке, до создания PR.
**Место:** чат. В статью задачи и в тело PR не дублируется.

## Что должно быть

Руководитель должен понять логику и увидеть, **как двигаются данные**, не читая код целиком. Основа —
**текстовый алгоритм + трассировка на наших данных**. Файлы и строки — **якоря**, по ним прыгаешь
в код и проверяешь.

## Структура

1. **Что делает** — 2–5 строк: назначение и место в системе.
2. **Карта изменения** — обязательно, если файлов больше двух: файлы в порядке прохождения данных,
   например `вход → Controller → Service → Repository → миграция → фронт`. Для сквозной правки это
   главный навигатор.
3. **Блоки** — по одному на смысловой узел:
   **Блок N. <название> — `<файл>`, строки X–Y**
   - **Алгоритм** — нумерованные шаги по-русски: откуда берём данные → что проверяем → что делаем
     при каком условии.
   - **Трассировка на наших данных** — конкретные значения: вход → что получилось. Обязательно ветки:
     «нет данных», «ошибка», «отладочный режим».
4. **Тонкости и ловушки** — что неочевидно и где легко ошибиться (пример: метка антифлуда пишется
   до отправки, поэтому при сбое SMTP повторной попытки в течение часа не будет).
5. **Чего сознательно не делает** — для скриптов и фич с границами: «не проверяет / не умеет» с причиной.

## Файлы и строки — можно и нужно

- Имя файла и диапазон строк **указываем**: «`send()` — `ops/vps-health.sh`, строки 42–80».
- Строки **группируем по смыслу** («12–33 — конфиг и дефолты»), а не по одной.
- Диапазоны могут «плыть» после правок — это нормально: смысл важнее точности, но якорь нужен.
- **Запрещено:** построчная таблица вместо объяснения («46 — if; 53 — printf»), пересказ кода,
  журнал работ, номера коммитов, логи прогонов.

## Бюджет

≤10 блоков; ≤7 шагов в алгоритме; ≤10 строк трассировки на блок. Больше — дроби: карта + блоки по узлам.

## Эталон (сокращённо)

**Карта:** cron → `ops/vps-health.sh` → `send()` → msmtp → почта.

**Блок 2. Конфиг и дефолты — `ops/vps-health.sh`, строки 12–33**
**Алгоритм:** 1) путь: `VPS_HEALTH_CONF` или `/etc/vps-health.conf`; 2) файл есть → выполнить его
в текущем shell; 3) настройка не задана или пуста → подставить дефолт.
**Трассировка:** `CONF=/etc/vps-health.conf` → файл есть → `MAIL_TO=…`, `DISK_WARN=80`,
`CONTAINERS="php messenger-worker …"` → дефолты не меняются (кроме `DRY_RUN=0`, его в конфиге нет).
Конфига нет → скрипт работает на дефолтах.

**Блок 3. `send()` — строки 42–80**
**Алгоритм:** 1) `_now` в секундах; 2) файл `last-<key>`; 3) прошло < COOLDOWN → лог skip, выход;
4) записать метку; 5) тема `SUBJECT_TAG HOST_TAG: subj` + base64 RFC 2047; 6) собрать MIME;
7) `DRY_RUN=1` → только лог; 8) иначе msmtp → sent/FAILED.
**Трассировка:** nginx down → `problems=2` → `send alert "проблем: 2"` → файла `last-alert` нет →
метка `1763040334` → тема «[VPS][bloodcontrol] …» → msmtp → «sent: проблем: 2».
