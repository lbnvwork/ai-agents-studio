# Аквариум — как код идёт по шагам

**Триггер:** «делай пулрек, пиши аквариум» (или «пиши аквариум»).
**Момент:** после всех коммитов в ветке, до создания PR. **Место:** чат (в статью и PR не дублируется).

## Формат шага (основа всего)

**Шаг = элемент markdown-списка** (строка, начинающаяся с `- ` или `1.`), один пункт = один шаг.
Внутри пункта: диапазон строк → что происходит (условие и эффект), при необходимости — файл.

```
- 55–56 — прочитать --login, --name, --role
- 57–66 — любого нет → <error>…</error>, код 2
- 79 — для врача/лаборанта: scope = hospital, ЛПУ должно существовать
```

**Шагом НЕ является:** строка таблицы, абзац текста, заголовок `### 96–101`, пункт с тремя действиями
через запятую. Если действий несколько — несколько пунктов; вложенные ветки — вложенный список.

**Файл в пункте** указывается, когда шаг уходит из файла блока — например, «→ deny(), `AbstractAdminCommand.php:83–106`».

Не таблица, не сплошной текст: каждый шаг — отдельная строка списка. Так читается как лог дебаггера.

## Точки остановки — аквариум читают с дебаггером

Шагов мало: по ним видно, **что** происходит, но не видно, **где встать и что должно быть в данных**.
Поэтому каждый блок, кроме шагов, содержит три элемента.

**1. ⏸ Остановка — одна строка на блок.** `<файл>:<строка>`, где читателю остановиться, и что
именно он там смотрит. Это место перед ключевым решением: проверка права, ветка `dry-run`,
вызов сервиса, `persist`/`flush`. Хочется две остановки — значит это два блока.

```
**⏸ Остановка:** `api/src/…/UserAdministrationService.php:103` — перед `persist()` пользователя.
```

**2. Обязательно в этот момент — 2–5 пунктов.** Только те значения, строки БД и флаги, без которых
чтение бессмысленно. Формат «что = чему», с конкретикой:

```
**Обязательно в этот момент:** `$dryRun = false`; `$login = "cmd.new.doctor"`; `$role = "ROLE_DOCTOR"`;
`$hospital->getId() = 12`; в БД у актора `roles = ["ROLE_ADMIN"]`.
```

Несущественное не упоминаем вовсе: списка «что игнорировать» не пишем, прокси Doctrine, `modDt`,
служебные счётчики и прочий шум просто отсутствуют. Пункт, который не влияет на ветку, — лишний.

**3. Трассировки — две.** `(норма)` — как данные идут, когда всё хорошо; `(ветка/ошибка)` — dry-run,
отказ правила, пустой справочник, невалидный ввод. Значения конкретные, из наших данных.

**Значения проверяем, а не сочиняем.** Дебаггер, тест-сид, `sed -n 'X,Yp'`, запрос к тестовой БД
(`symfony_test`) — что доступно. Если проверить нельзя, помечаем как допущение прямо в трассировке.

## Жёсткие правила (из-за них были срывы)

1. **Каждый диапазон — с путём файла.** Без файла запись «строки 96–101» лжёт: такой диапазон
   почти всегда есть и в другом файле. В шаге пиши файл, если он отличается от файла блока.
2. **Блок не пересекает файлы молча.** Заголовок блока объявляет файл, и весь блок — про него.
   Переход в другой файл — либо новый блок, либо явная строка: `→ вызов: <файл>:<строки>`.
3. **Номера — по конкретному коммиту.** В шапке аквариума: `номера по <ветка>@<sha7>`. После правок
   они сдвинутся, и это нормально.
4. **Сверка перед сдачей:** каждый диапазон существует в указанном файле (`sed -n 'X,Yp' <файл>`);
   метод, названный в шаге, действительно там. Если сдвинулось — поправь, не посылай.
5. **В каждом блоке есть ⏸ Остановка и «Обязательно в этот момент».** Блок без них — не аквариум,
   а пересказ кода: читатель не поймёт, где встать в дебаггере и что должно быть в переменных.
6. **Запрещено:** таблицы вместо шагов, сплошной текст без шагов, диапазон без файла, заголовок
   блока с файлом A, а содержимое из файла B, список «что игнорировать» и прочий шум.

## Ссылки на файлы (прыжок в код)

В шаге и в карте потока даём **кликабельный путь** — тогда из чата прыгаешь прямо в файл.

**Работает ровно один формат — путь в косых кавычках, без номера строки, относительно корня рабочего каталога:**

```
- 96–101 — `reason()` и `actor()` — `api/src/Ibs/Context/SecurityIdentity/Command/UserCreateCommand.php`, строки 96–101
```

Проверено на живых чатах: кликается **только** `` `путь/от/корня` ``. Не работают:

- абсолютный путь и `file://`-ссылки (синяя, но не переходит);
- `путь:строка` внутри кавычек (плашка не появляется);
- путь, которого нет в рабочем дереве.

Поэтому:

- путь — **от корня того чата, где написан аквариум** (у дева это `api/src/…`, у РП в корне `lazurit` — `projects/ibs/ibs-dev-jun/api/src/…`);
- **строки пишем рядом текстом**, не приклеиваем к пути;
- перед сдачей проверь, что файл существует (`ls`); для файла из ветки PR ветка должна быть выкачана, иначе плашка мертва;
- в карте потока — по такому пути на каждый файл цепочки.


## Структура аквариума

1. **Что делает** — 2–5 строк.
2. **Карта потока** — обязательна, если файлов ≥3: цепочка с файлами и строками, чтобы видеть,
   что ничего не «перескакивает»:
   ```
   тест: tests/…/UserCreateCommandTest.php:60–91
     → UserCreateCommand.php:51–94   разбор опций
     → UserCreateCommand.php:96–101  reason()/actor() → AbstractAdminCommand.php:52–64, 44–51
     → UserCreateCommand.php:103–109 create() → UserAdministrationService.php:58–115
   ```
3. **Блоки** — по одному на смысловой узел:
   `Блок N. <смысл> — <файл>, <метод>, строки X–Y` → шаги → **⏸ Остановка** →
   **Обязательно в этот момент** → **трассировки (норма / ветка или ошибка)**.
4. **Тонкости и ловушки** — где легко ошибиться (порядок проверок до записи, dry-run пишет ok и т.п.).
5. **Чего сознательно не делает** — для скриптов/фич с границами.

## Бюджет

≤10 блоков; ≤12 шагов на блок; ≤5 пунктов «Обязательно в этот момент»; ≤6 строк на каждую трассировку.
Больше — дроби по узлам.

## Эталон (формат с точками остановки)

**Блок 1. Сборка пользователя и ветка dry-run — `api/src/Ibs/Context/SecurityIdentity/Service/UserAdministrationService.php`, `create`, строки 84–101**
**Шаги:**
- 84–88 — собрать `User`: логин, ФИО, `roles = [<роль>]`, `must_change_password = true`.
- 90–91 — 32 случайных байта → захешировать как временный пароль.
- 93–96 — для врача собрать кадровую запись с ЛПУ и привязать к пользователю.
- 98–101 — `--dry-run`: вернуть `['user' => <объект>, 'token' => '']`, `persist`/`flush` не вызываются.
**⏸ Остановка:** `api/src/Ibs/Context/SecurityIdentity/Service/UserAdministrationService.php:103` — перед `persist()` кадровой записи.
**Обязательно в этот момент:** `$dryRun = false`; `$login = "cmd.new.doctor"`; `$role = "ROLE_DOCTOR"`; `$hospital->getId() = 12`; `$user->getPassword()` — bcrypt-хеш, не пустая строка; `$personnel` — объект, а не `null`.
**Трассировка (норма):** `$dryRun=false` → `persist($personnel)`, `persist($user)`, `flush()` → новые строки в `users` и `medical_personnel` (`hospital_id=12`), дальше Шаг 2.
**Трассировка (dry-run):** `$dryRun=true` → выход на `:100` → в БД пусто, `token = ''`, команда печатает «изменения не применены, токен не выпущен».

**Блок 2. Выпуск токена — `api/src/Ibs/Context/SecurityIdentity/Service/OneTimeTokenService.php`, `issue`, строки 37–52**
**Шаги:**
- 38 — 32 случайных байта → открытый токен (64 hex).
- 40–45 — собрать `OneTimeToken`: пользователь, автор, назначение по коду, `sha256(токен)`, `expires_at = now + 24 ч`.
- 47–49 — `persist` + `flush` → INSERT в `one_time_token`.
- 51 — вернуть открытый токен (в БД его нет).
**⏸ Остановка:** `api/src/Ibs/Context/SecurityIdentity/Service/OneTimeTokenService.php:47` — перед `persist()` токена.
**Обязательно в этот момент:** `strlen($plainToken) = 64`; `purposeByCode('password_reset')` вернул строку справочника с `id = 1`; `$token->getTokenHash()` ≠ `$plainToken` (это `sha256`).
**Трассировка (норма):** открытый `807c66…` → в БД `629c0e9d…` (`sha256`), `purpose_id = 1`, `expires_at` на сутки вперёд, в ответе открытый токен.
**Трассировка (ошибка):** кода `password_reset` нет в справочнике → `AdministrationDeniedException` «Назначение токена «password_reset» отсутствует в справочнике…», INSERT не выполняется.

## Чек-лист

- [ ] Каждый диапазон — с файлом; блок не пересекает файлы молча.
- [ ] Шаги — пошаговым списком, не таблицей и не абзацами.
- [ ] В каждом блоке есть **⏸ Остановка** (`файл:строка`) и **Обязательно в этот момент** (2–5 пунктов, только существенное).
- [ ] Трассировок две: норма и ветка/ошибка (dry-run, отказ, пустой справочник, невалидный ввод).
- [ ] Значения в трассировках проверены (дебаггер, тест-сид, БД) или помечены как допущение.
- [ ] Списка «что игнорировать» и прочего шума нет — лишнее просто не упомянуто.
- [ ] Есть карта потока (если файлов ≥3).
- [ ] Диапазоны сверены с файлами на указанном коммите.
- [ ] Пути к файлам — в косых кавычках от корня чата (кликаются), строки — рядом текстом.
