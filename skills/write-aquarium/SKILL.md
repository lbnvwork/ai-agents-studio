# Аквариум — как код идёт по шагам

**Триггер:** «делай пулрек, пиши аквариум» (или «пиши аквариум»).
**Момент:** после всех коммитов в ветке, до создания PR. **Место:** чат (в статью и PR не дублируется).

## Формат шага (основа всего)

**Шаг = элемент markdown-списка** (строка, начинающаяся с `- ` или `1.`), один пункт = один шаг.
Внутри пункта: диапазон строк → что происходит (условие и эффект), при необходимости — файл.

```
- 55–56 — прочитать --login, --name, --role
- 57–66 — любого нет → <error>…</error>, код 2
- 79 — для врача/лаборанта: scope = hospital, ЛПУ должно существовать
```

**Шагом НЕ является:** строка таблицы, абзац текста, заголовок `### 96–101`, пункт с тремя действиями
через запятую. Если действий несколько — несколько пунктов; вложенные ветки — вложенный список.

**Файл в пункте** указывается, когда шаг уходит из файла блока — например, «→ deny(), `AbstractAdminCommand.php:83–106`».

Не таблица, не сплошной текст: каждый шаг — отдельная строка списка. Так читается как лог дебаггера.

## Жёсткие правила (из-за них были срывы)

1. **Каждый диапазон — с путём файла.** Без файла запись «строки 96–101» лжёт: такой диапазон
   почти всегда есть и в другом файле. В шаге пиши файл, если он отличается от файла блока.
2. **Блок не пересекает файлы молча.** Заголовок блока объявляет файл, и весь блок — про него.
   Переход в другой файл — либо новый блок, либо явная строка: `→ вызов: <файл>:<строки>`.
3. **Номера — по конкретному коммиту.** В шапке аквариума: `номера по <ветка>@<sha7>`. После правок
   они сдвинутся, и это нормально.
4. **Сверка перед сдачей:** каждый диапазон существует в указанном файле (`sed -n 'X,Yp' <файл>`);
   метод, названный в шаге, действительно там. Если сдвинулось — поправь, не посылай.
5. **Запрещено:** таблицы вместо шагов, сплошной текст без шагов, диапазон без файла, заголовок
   блока с файлом A, а содержимое из файла B.

## Ссылки на файлы (прыжок в код)

В шаге и в карте потока даём **кликабельный путь** — тогда из чата прыгаешь прямо в файл.

**Работает ровно один формат — путь в косых кавычках, без номера строки, относительно корня рабочего каталога:**

```
- 96–101 — `reason()` и `actor()` — `api/src/Ibs/Context/SecurityIdentity/Command/UserCreateCommand.php`, строки 96–101
```

Проверено на живых чатах: кликается **только** `` `путь/от/корня` ``. Не работают:

- абсолютный путь и `file://`-ссылки (синяя, но не переходит);
- `путь:строка` внутри кавычек (плашка не появляется);
- путь, которого нет в рабочем дереве.

Поэтому:

- путь — **от корня того чата, где написан аквариум** (у дева это `api/src/…`, у РП в корне `lazurit` — `projects/ibs/ibs-dev-jun/api/src/…`);
- **строки пишем рядом текстом**, не приклеиваем к пути;
- перед сдачей проверь, что файл существует (`ls`); для файла из ветки PR ветка должна быть выкачана, иначе плашка мертва;
- в карте потока — по такому пути на каждый файл цепочки.


## Структура аквариума

1. **Что делает** — 2–5 строк.
2. **Карта потока** — обязательна, если файлов ≥3: цепочка с файлами и строками, чтобы видеть,
   что ничего не «перескакивает»:
   ```
   тест: tests/…/UserCreateCommandTest.php:60–91
     → UserCreateCommand.php:51–94   разбор опций
     → UserCreateCommand.php:96–101  reason()/actor() → AbstractAdminCommand.php:52–64, 44–51
     → UserCreateCommand.php:103–109 create() → UserAdministrationService.php:58–115
   ```
3. **Блоки** — по одному на смысловой узел:
   `Блок N. <смысл> — <файл>, <метод>, строки X–Y` → шаги → **трассировка на наших данных**.
4. **Тонкости и ловушки** — где легко ошибиться (порядок проверок до записи, dry-run пишет ok и т.п.).
5. **Чего сознательно не делает** — для скриптов/фич с границами.

## Бюджет

≤10 блоков; ≤12 шагов на блок; трассировка ≤8 строк на блок. Больше — дроби по узлам.

## Эталон (из нашей же задачи 5.43)

**Блок 1. Разбор опций — `api/src/Ibs/Context/SecurityIdentity/Command/UserCreateCommand.php`, метод `execute`, строки 51–94**
**Шаги:**
- 55–56 — прочитать `--login`, `--name`, `--role`.
- 57–66 — любого нет → `<error>Опции --login, --name и --role обязательны.</error>`, код 2.
- 68–75 — прочитать `--scope-level`, `--hospital`, `--scope-id`; `--hospital` перекрывает уровень и id.
- 77–85 — уровень пуст → сообщение про `--scope-level`/`--hospital`, код 2.
- 87–91 — id не число → «`--scope-id` должен быть числом», код 2.
- 93–94 — привести id к int, прочитать `--dry-run`.
**Трассировка:** без `--name` → текст ошибки, exit=2, журнал не пишется (ошибка ввода ≠ отказ правила).

**Блок 2. Делегирование и вывод — тот же `api/src/Ibs/Context/SecurityIdentity/Command/UserCreateCommand.php`, `execute`, строки 96–139**
**Шаги:**
- 96–101 — `reason()` и `actor()`; исключение → `deny('create-user', …)` (`AbstractAdminCommand.php:83–106`).
- 103–109 — `UserAdministrationService::create(…)`; исключение → `deny` с контекстом.
- 111–120 — `logOk('create-user', …)` → `AbstractAdminCommand.php:107–110` → `FileAdminActionLogger.php:27–50`.
- 122–128 — печать «Пользователь «…» создан: роль …, scope …».
- 130–134 — при `--dry-run`: «изменения не применены, токен не выпущен», exit=0.
- 136–139 — печать одноразового токена.
**Трассировка:** без `--reason` → отказ, exit=1, в журнале `denied` с контекстом; с валидными опциями → пользователь создан, `create-user/ok`, 64-hex токен в stdout.

## Чек-лист

- [ ] Каждый диапазон — с файлом; блок не пересекает файлы молча.
- [ ] Шаги — пошаговым списком, не таблицей и не абзацами.
- [ ] Есть карта потока (если файлов ≥3).
- [ ] Трассировка с реальными значениями и ветками (ошибка / dry-run / нет данных).
- [ ] Диапазоны сверены с файлами на указанном коммите.
- [ ] Пути к файлам — в косых кавычках от корня чата (кликаются), строки — рядом текстом.
