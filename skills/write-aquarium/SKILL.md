# Аквариум — как код идёт по шагам

**Триггер:** «делай пулрек, пиши аквариум» (или «пиши аквариум»).
**Момент:** после всех коммитов в ветке, до создания PR. **Место:** чат (в статью и PR не дублируется).

## Формат шага (основа всего)

**Шаг = элемент markdown-списка** (строка, начинающаяся с `- ` или `1.`), один пункт = один шаг.
Внутри пункта: диапазон строк → что происходит (условие и эффект), при необходимости — файл.

```
- 55–56 — прочитать --login, --name, --role
- 57–66 — любого нет → <error>…</error>, код 2
- 79 — для врача/лаборанта: scope = hospital, ЛПУ должно существовать
```

**Шагом НЕ является:** строка таблицы, абзац текста, заголовок `### 96–101`, пункт с тремя действиями
через запятую. Если действий несколько — несколько пунктов; вложенные ветки — вложенный список.

**Файл в пункте** указывается, когда шаг уходит из файла блока — например, «→ deny(), `AbstractAdminCommand.php:83–106`».

Не таблица, не сплошной текст: каждый шаг — отдельная строка списка. Так читается как лог дебаггера.

## Блок: что в нём обязательно

Шесть элементов; блок без любого из них не принимается.

**1. Фрагмент кода.** 5–15 строк из файла блока, номера — в комментариях (`// 31`), только
существенное, пропуски — `…`. Для теста — фрагмент теста. Читатель сверяет код глазами, а не
пересказ: без примера блок читается хуже и теряет смысл.

**2. Шаги** — списком (см. «Формат шага»).

**3. ⏸ Остановка** — `<файл>:<строка>`, куда встать в дебаггере и что смотреть: перед ключевым
решением (право, dry-run, вызов сервиса, `persist`/`flush`). Одна на блок.

**4. Обязательно в этот момент** — 2–5 пунктов «что = чему»: только значения и строки БД, без
которых чтение бессмысленно (`$dryRun = false`, `roles = ["ROLE_ADMIN"]`). Несущественное просто
не упоминаем — списка «что игнорировать» нет.

**5. Трассировка (норма)** — имя позитивного теста + как идут данные при успехе.

**6. Негативные ветки — с именем теста.** Сценарий → покрывающий тест; нет теста — «стоит
добавить». Ветки ищем **по покрытию, а не по памяти**: прогон `XDEBUG_MODE=coverage … --coverage-text`
или clover + `count="0"` (скилл `check-coverage`) показывает, что реально не проверено.

Значения проверяем, а не сочиняем: дебаггер, тест-сид, `sed -n`, `symfony_test`; иначе — помечаем допущением.

## Жёсткие правила (из-за них были срывы)

1. **Каждый диапазон — с путём файла.** Без файла запись «строки 96–101» лжёт: такой диапазон
   почти всегда есть и в другом файле. В шаге пиши файл, если он отличается от файла блока.
2. **Блок не пересекает файлы молча.** Заголовок блока объявляет файл, и весь блок — про него.
   Переход в другой файл — либо новый блок, либо явная строка: `→ вызов: <файл>:<строки>`.
3. **Номера — по конкретному коммиту.** В шапке аквариума: `номера по <ветка>@<sha7>`. После правок
   они сдвинутся, и это нормально.
4. **Сверка перед сдачей:** каждый диапазон существует в указанном файле (`sed -n 'X,Yp' <файл>`);
   метод, названный в шаге, действительно там. Если сдвинулось — поправь, не посылай.
5. **В каждом блоке есть ⏸ Остановка, «Обязательно в этот момент» и негативные ветки с тестами.**
   Блок без них — пересказ кода: не видно, где встать в дебаггере, что в переменных и чем проверен отказ.
6. **Запрещено:** таблицы вместо шагов, сплошной текст без шагов, диапазон без файла, заголовок
   блока с файлом A, а содержимое из файла B, список «что игнорировать» и прочий шум.

## Ссылки на файлы (прыжок в код)

Кликается **только** путь в косых кавычках, без номера строки, от корня чата:
`` `api/src/…/UserCreateCommand.php` ``, строки 96–101. Абсолютные пути, `file://`-ссылки,
`путь:строка` внутри кавычек и несуществующие файлы — не работают. Строки пишем рядом текстом;
перед сдачей проверь `ls` (файл из ветки PR — ветка должна быть выкачана). В карте потока —
такой путь на каждый файл цепочки.


## Структура аквариума

0. **Как включить дебаггер** — первым блоком, всегда:
   - VS Code → Run & Debug → конфиг `Listen for Xdebug (<клон>)` → F5 (слушатель 9003 один);
   - прогон с триггером: `docker compose exec -T -e XDEBUG_SESSION=1 php sh -lc 'vendor/bin/phpunit --filter "<Тест>"'`;
   - брейкпоинты — в файлах клона и по тем же путям, что в `pathMappings` (симлинк `docs/…/projects` ломает маппинг);
   - связь: `tail -5 /tmp/xdebug.log` в контейнере → `Connected to debugging client`.
1. **Что делает** — 2–5 строк.
2. **Карта потока** — если файлов ≥3: цепочка с файлами и строками, начинается с позитивного теста
   (`тест: <файл>:<строка> <метод>` → `Command.php:51–94` …).
3. **Блоки** — по одному на смысловой узел, в порядке из раздела «Блок: что в нём обязательно»:
   код → шаги → ⏸ Остановка → Обязательно в этот момент → трассировка → негативные ветки.
4. **Тонкости и ловушки** — где легко ошибиться (порядок проверок до записи, dry-run пишет ok и т.п.).
5. **Чего сознательно не делает** — для скриптов/фич с границами.

## Бюджет

≤10 блоков; ≤12 шагов на блок; ≤5 пунктов «Обязательно в этот момент»; ≤5 негативных веток на блок.

## Эталон блока

**Блок 1. Сборка пользователя — `api/src/Ibs/Context/SecurityIdentity/Service/UserAdministrationService.php`, `create`, 84–101**
```php
$user = (new User())->setLogin($login)->setUserName($name)->setRoles([$role]);      // 84–88
$temporaryPassword = bin2hex(random_bytes(16));                                      // 90
$user->setPassword($this->passwordHasher->hashPassword($user, $temporaryPassword));  // 91
if ($dryRun) { return ['user' => $user, 'token' => '']; }                            // 98–101
```
**Шаги:**
- 84–88 — собрать `User`: логин, ФИО, `roles`, `must_change_password = true`.
- 90–91 — 32 случайных байта → bcrypt как временный пароль.
- 93–96 — для врача кадровая запись с ЛПУ.
- 98–101 — `--dry-run`: вернуть план, `persist`/`flush` не вызываются.
**⏸ Остановка:** `…/UserAdministrationService.php:103` — перед `persist()` кадровой записи.
**Обязательно в этот момент:** `$dryRun = false`; `$login = "cmd.new.doctor"`; `$hospital->getId() = 12`; `$user->getPassword()` — bcrypt-хеш.
**Трассировка (норма, `UserCreateCommandTest::testCreatesUserWithTokenAndWritesOkToJournal`, `…/UserCreateCommandTest.php:60`):** INSERT в `users` и `medical_personnel` (`hospital_id=12`) → Блок 2.
**Негативные ветки:** `--dry-run` → `testDryRunCreatesNothing` (`…:130`); нет `--reason` → `testReasonIsRequiredAndJournaledAsDenied` (`…:151`); пустой справочник назначений → **теста нет — стоит добавить**.

## Чек-лист

- [ ] Первым блоком — **как включить дебаггер** (конфиг, команда с `XDEBUG_SESSION=1`, проверка лога).
- [ ] В каждом блоке — **фрагмент кода** с номерами строк в комментариях, затем шаги.
- [ ] Каждый диапазон — с файлом; блок не пересекает файлы молча.
- [ ] В каждом блоке есть **⏸ Остановка** (`файл:строка`) и **Обязательно в этот момент** (2–5 пунктов).
- [ ] Негативные ветки сверены с покрытием (Xdebug/clover), у каждой — имя теста или «стоит добавить».
- [ ] Значения проверены (дебаггер, тест-сид, БД) или помечены как допущение.
- [ ] Списка «что игнорировать» и прочего шума нет.
- [ ] Есть карта потока (если файлов ≥3); диапазоны сверены с файлами на указанном коммите.
- [ ] Пути к файлам — в косых кавычках от корня чата (кликаются), строки — рядом текстом.
