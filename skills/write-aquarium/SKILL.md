# Аквариум — что изменили и зачем

**Триггер (единственный):** руководитель говорит «делай пулрек, пиши аквариум» (или «пиши аквариум»).
**Момент:** конец разработки, **после всех коммитов в ветке**, до создания PR.
**Место:** **чат**. В статью задачи не пишется, в PR-тело не дублируется.
**Основа:** `git diff --name-only <base>...HEAD` — только реально изменённые файлы.

## Формат (две части)

### 1. Логика в целом
2–5 строк: что меняется по сути и как система работает после изменения. Без пересказа диффа.

### 2. Пофайлово

| Файл | Что изменено | Зачем |
|---|---|---|
| `src/…/Foo.php` | добавлена проверка X в методе Y | закрывает СЦ-2 |
| `migrations/Version…php` | новое поле `dose_note` | хранение примечания к дозе |

## Правила

- Строка на **каждый** изменённый файл: пропусков нет, «заодно упомянутых» файлов тоже нет.
- Одна строка — 1–2 предложения по делу: что именно поменялось и для чего.
- Миграции, конфиги, фикстуры, шаблоны — такие же файлы, их указываем.
- Файлов больше 20 — группируй по модулям/пакетам, но ни один изменённый файл не теряется.
- Бюджет: ≤25 строк таблицы. Больше — значит дифф слишком широкий (вопрос к Лиду), а не повод писать длиннее.
- Номера коммитов, журнал работ, отчёты `СДЕЛАНО/ФАЙЛЫ`, логи прогонов — не пишем (это `git log`, чат и PR).

## Чек-лист

- [ ] Список файлов совпадает с `git diff --name-only` (ничего не пропущено, ничего лишнего).
- [ ] «Логика в целом» — 2–5 строк, без пересказа кода.
- [ ] По каждому файлу понятно «что» и «зачем».
- [ ] Нет журнала, коммитов, отчётов и логов.
