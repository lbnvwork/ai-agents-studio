# Write-aquarium

«Аквариум» отвечает на один вопрос: **закрыт ли каждый сценарий из статьи кодом и тестом**. Это таблица, а не рассказ.
Раньше скилл требовал дебаггер-трассировку «до 10–15 шагов с фактическими значениями переменных» — на одной из задач
это дало **971 строку**, которую никто не читает. Так больше не пишем.

## Когда писать
- На **вехе**: реализация → ревью → правки по ревью. Не после каждого коммита.
- Перед PR (черновик) и после ревью (обновление статусов).
- Если код под сценарий не менялся — строку не трогаем.

## Формат (единственный)

| # | Сценарий | Где в коде | Тест | Статус |
|---|---|---|---|---|
| СЦ-1 | <название из секции «Сценарии»> | `Файл.php:метод` / `Component.vue` | `SomeTest`, `foo.spec.js` | ✅ / ⚠️ / ❌ / вне скоупа (причина) |

- Строка = сценарий из секции «Сценарии» статьи. Сценариев 12 — строк 12.
- «Где в коде» — файл и метод (или модуль), без пошаговых пересказов.
- «Тест» — имя теста, который этот сценарий проверяет; теста нет → `❌` и причина.
- «Статус»: `✅` реализовано и покрыто, `⚠️` реализовано без теста, `❌` не сделано, `вне скоупа (причина)`.
- **Бюджет:** ≤15 строк таблицы. Сценариев больше — значит сценарии в статье нарезаны слишком мелко (вопрос к Лиду), а не повод писать больше.
- Дополнительный текст — только для сложного места: `### Трассировка <компонент>` ≤10 строк (вход → ключевые вызовы → выход, конкретные значения коротко).

## Что НЕ пишем
- Журнал работ и номера коммитов — это `git log` и чек-лист «План реализации».
- Отчёты `СДЕЛАНО/ФАЙЛЫ/БЛОКЕРЫ/ЗАМЕТКИ` — это чат руководителю и квитанция коммита.
- Логи прогонов и дампы вывода — это PR.
- Пошаговые пересказы кода, если по шагам всё видно из таблицы.

## Чек-лист
- [ ] Строка на каждый сценарий (или явное «вне скоупа (причина)»).
- [ ] В «Где в коде» — реальные файлы и методы из репозитория.
- [ ] В «Тест» — имена тестов, которые существуют и проходят.
- [ ] Бюджет соблюдён (≤15 строк таблицы; доп. трассировка ≤10 строк на компонент).
- [ ] Журнала, отчётов, номеров коммитов и логов в секции нет.
