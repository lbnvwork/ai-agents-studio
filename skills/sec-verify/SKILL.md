# sec-verify — приёмка безопасности после тестирования

## Вход

- `S.NN` — код задачи (обязателен; нет — спроси).
- Проект — по умолчанию `ibs`; контур — тестовый (`test.bloodcontrol.ru`) или стенд DevOps.
- Больше ничего не нужно: отчёт Тестера и запись ревью находишь сам.

## 1. Контекст

```bash
ART=$(ls src/ibs-docs/03-Задачи/Спринты/*/S.NN.*.md 2>/dev/null | head -1); echo "$ART"
sed -n '1,120p' "$ART"
grep -n 'Комментарии: Тест\|Результат\|Реализация\|Вердикт безопасности' "$ART" | head -20
ls docs/аудит/записи/S.NN-review-*.md 2>/dev/null
```

Читай: отчёт Тестера (что проверялось, чем, что не проверено), «Результат», запись `sec-review`
(какие находки были и с каким severity), статус PR/мержа.

## 2. Что проверить

1. **Закрытие находок ревью** — по каждой: исправлено / принятый риск / открыта (со ссылкой).
2. **Abuse cases** — прошли на контуре: перебор, обход авторизации, чужой id, инъекции, загрузки, SSRF, лимиты.
3. **ПДн** — в логах приложения и веб-сервера, ответах API, ошибках, аналитике, письмах: не утекают.
4. **RBAC/IDOR** — по ролям: чужой пациент/ЛПУ/приём недоступен; эскалация ролей закрыта.
5. **DAST** — если включён в гейты: находки разобраны, critical/high закрыты.
6. **Секреты и артефакты** — в CI, сборке, конфигах контура нет ключей.
7. **Миграции** — права, откат, отсутствие destructive-операций без подтверждения.
8. **Чек-лист проекта** — сверка с `docs/09-Служебное/Регламенты/Security-чеклист.md`:
   закрыто / нет / не применимо + доказательство.

## 3. Вердикт для «Готово»

- **`можно в Готово`** — все пункты закрыты, доказательства есть.
- **`замечания`** — перечень, кто и к какому сроку закрывает (возврат в «Тестирую»).
- **`блокер`** — critical/high или открытая утечка ПДн: в «Готово» нельзя.

Плюс **остаточные риски** (что принято и кем) и **что не проверено** (с причиной).

## 4. Релизный гейт

Если задача — часть релиза, добавь проверку: модель угроз и поверхность атаки обновлены
(`sec-threat-model`), SBOM сформирован, реестр уязвимостей актуален (`sec-audit`).
Не выполнено — «в Готово нельзя».

## 5. Формат и куда записать

- Полный разбор — `<проект>/docs/Безопасность/Записи/<S.NN>-verify-<ГГГГ-ММ-ДД>.md`.
- ПМу — блок **«Вердикт безопасности»** для статьи/PR: вердикт, находки, остаточные риски, доказательства.
- Статью и карточки не правишь; код не коммитишь.

## Статья и канал

- В статье задачи дополняй раздел `## Безопасность`: кратко (можно в Готово / замечания / блокер) + ссылка на `Безопасность/Записи/<S.NN>-verify-<дата>.md`.
- Запись в канал (создастся сама):
  `cd src/ibs-docs && python3 09-Служебное/Скрипты/comment_stamp.py --project <проект> --who "Ной (безопасность)" --type вердикт --file "<статья>" --write "можно в Готово / замечания / блокер; запись — Безопасность/Записи/<S.NN>-verify-<дата>.md"`
- Нет rw-клона проекта — отдай готовый блок ПМу; он вставит в раздел и канал.

## Границы

Не заменяешь тестирование (свои проверки — только безопасность); не поднимаешь свой стек;
прод и боевая БД — только чтение; реальные ПДн не копируешь.
