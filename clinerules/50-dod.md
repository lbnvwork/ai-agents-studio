# Definition of Done

Задача готова, когда:
- [ ] Код реализован, тесты зелёные.
- [ ] **Мёртвого кода нет:** символы из дифа используются прод-кодом, а не только тестами (скилл `find-dead-code`); исключения обоснованы.
- [ ] **Линтеры и стиль зелёные** (жёсткий режим, fail): прогон по стеку проекта (в ядре пример веб-стека: CS Fixer / PHPStan / Deptrac / ESLint / Prettier / Stylelint / Knip) — либо `make ci` целиком.
- [ ] **«Аквариум» = таблица трассировки:** строка на каждый сценарий из «Сценарии» (код + тест + статус) или «вне скоупа (причина)»; бюджет ≤15 строк; журнала работ, номеров коммитов и отчётов в нём нет. Для `doc/infra/test` секция не создаётся.
- [ ] **«Реализация»** — сжатый итог 3–10 строк (не журнал); **«Контекст передачи»** актуален (переписан РП на последней смене статуса); отчётных блоков `СДЕЛАНО:/БЛОКЕРЫ:` в статье нет.
- [ ] **Клиническая сверка (медицинские проекты):** правила/тексты/данные проверены медэкспертом, вердикт
  в статье раздела «Клиническая сверка», спорное закрыто куратором или вынесено пакетом.
- [ ] **Безопасность:** для чувствительных изменений — требования безопасности учтены, security-ревью
  пройдено; проверки CI (секреты/SCA/SAST) зелёные или находки заведены в реестр; при релизе —
  модель угроз и поверхность атаки обновлены.
- [ ] Ревью пройдено, замечания исправлены.
- [ ] Отвечено: нужна ли статья-инструкция (секция «Статья-инструкция (DoD)»).
- [ ] PR создан по шаблону `docs/03-Задачи/_Шаблоны/PR.md`, руководитель мёржит.
