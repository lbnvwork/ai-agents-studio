# Definition of Done

Задача готова, когда:
- [ ] Код реализован, тесты зелёные.
- [ ] **Мёртвого кода нет:** символы из дифа используются прод-кодом, а не только тестами (скилл `find-dead-code`); исключения обоснованы.
- [ ] **`make ci` зелёный** (линтеры + тесты + сборка + метрики, жёсткий режим); в отчёте и PR — строка итога (`make ci OK: …` / `упало N из M — …`). Нет `make ci` — fallback из скилла `run-tests` с фактическим перечнем команд.
- [ ] **«Аквариум» = таблица трассировки:** строка на каждый сценарий (код + тест + статус) или «вне скоупа (причина)»; ≤15 строк; без журнала работ, номеров коммитов и отчётов. Для `doc/infra/test` секция не создаётся.
- [ ] **«Реализация»** — сжатый итог 3–10 строк (не журнал); **«Контекст передачи»** актуален (переписан РП при последней смене статуса); блоков `СДЕЛАНО:/БЛОКЕРЫ:` в статье нет.
- [ ] **Клиническая сверка (мед-проекты):** правила/тексты/данные проверены медэкспертом, вердикт в секции «Клиническая сверка», спорное закрыто куратором или вынесено пакетом.
- [ ] **Безопасность:** для чувствительных изменений требования безопасности учтены, security-ревью пройдено; проверки CI (секреты/SCA/SAST) зелёные или находки в реестре; при релизе модель угроз и поверхность атаки обновлены.
- [ ] Ревью пройдено, замечания исправлены.
- [ ] Отвечено: нужна ли статья-инструкция (секция «Статья-инструкция (DoD)»).
- [ ] PR создан по шаблону `docs/03-Задачи/_Шаблоны/PR.md`, руководитель мёржит.
