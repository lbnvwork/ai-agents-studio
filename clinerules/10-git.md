# Git-правила

- Ветка на каждую задачу от актуального `develop`: `S_NN_название`. **Создаёт первый, кто начинает менять код по задаче** (Дев; для e2e-тестов `tests/e2e/` — Тестер). Остальные участники работают в этой же ветке. Docs (`{{DOCS_REPO}}`) — без веток, пуш в `main`.
- Не пушить напрямую в `develop`/`main`.
- Коммиты атомарные, сообщение: `<код> <тип> <описание>` (напр. `N.N doc new ...`).
- Типы: `new`, `fix`, `ref`, `doc`, `infra`, `test`, `upd`.
- **ЗАПРЕТ КОММИТОВ АГЕНТАМ (критично, без исключений):**
  - Агент **никогда** не выполняет `git commit` — **ни в коде, ни в документации (`{{DOCS_REPO}}`)**. Агент присылает руководителю **название коммита**.
  - **Коммит делает только руководитель** (или РП по доверенности).
  - **Пуш** — агент выполняет **по отмашке руководителя**: `{{DOCS_REPO}}` — свободно (без PR), **только как `git pull --rebase origin main && git push origin main`**; `{{PROJECT}}` (код) — в ветку + `gh pr create` по отмашке.
  - По завершении работы — отчёт строгого формата (см. `20-workflow`) + `git diff`, затем **остановка**.
- **Название коммита — только строка `<код> <тип> <описание>`, без служебных пометок.** «(жду отмашки)», «(коммит/пуш за вами)», «(после ревью)», «TODO», скобки-пояснения в название не попадают — иначе они окажутся в `git log` (уже случалось). Служебное — в полях `СТАТУС`/`ЗАМЕТКИ` отчёта (формат — `20-workflow.md`).
- Секреты не коммитить — они в `.env` / `docs/09-Служебное/Доступы/` (gitignored).
- **Перед передачей на коммит — обязательная синхронизация:**
  - Код: `git fetch origin && git pull origin develop` (или merge develop в свою ветку); ветка `S_NN_название` создаётся только от актуального develop.
  - Docs (`{{DOCS_REPO}}`): `git pull origin main` перед правками и `git pull --rebase origin main` перед пушем (полный протокол — `11-docs.md`).
  - Не передавай название коммита, пока не синхронизирован с `develop`/`main` (иначе коммит руководителя ляжет на устаревшую базу → конфликт).
- Перед PR — прогон тестов и `git merge develop` в своей ветке.
- Документация — в отдельном репо `{{DOCS_REPO}}` (правила: `11-docs.md`), не в репо кода.
