# Воркфлоу и статусы

## Конвейер
РП → Аналитик → Лид → Дев+Тест → Ревью (Лид) → Тест (**+ сверка БЖ Аналитиком**) → **Деплой (DevOps)** → Готово.
Канбан: Надо делать → Анализ (Феб+Эйп) → Делаю → Ревью → Тестирую (Дев, Марк, **Феб**) → **Деплой** (Юлий) → Готово (+ Отложено/Отменено).
Статусы: `spec → planned → in_progress → review → testing → deploy → done` (+ `blocked`, `cancelled`).
Подробная схема — `docs/09-Служебное/Регламенты/Воркфлоу.md`; переходы и чек-листы РП — скилл `status-briefing`.
**WIP: 1–2 задачи в работе на агента.** Команды терминала — `21-terminal.md`.

## Запрет коммитов (критично, без исключений)
**Агент не выполняет `git commit`** — ни в коде, ни в документации (`{{DOCS_REPO}}`). Коммит — только руководитель (или РП по доверенности).
Пуш: `{{DOCS_REPO}}` — по отмашке, свободно, без PR; `{{PROJECT}}` (код) — в ветку + пулрек по отмашке.

## Отчёт вместо коммита
Полный отчёт — в «Комментарии» статьи задачи. В чат руководителю — **только блок `КОММИТЫ`** (строки-названия, копируются как есть). В чат РП — полный отчёт.

```
СДЕЛАНО:  <что сделано, кратко>
ФАЙЛЫ:    [код]  <путь в репо кода>
           [docs] <путь в репо доков>
БЛОКЕРЫ:  <есть/нет + что именно блокирует>
ЗАМЕТКИ:  <опционально>
```

Отдельным блоком — **названия коммитов, по одной строке**:
```
[код]  N.N fix <что исправлено>
[docs] N.N doc <что изменилось в доках>
```
После блока, вне его: `СТАТУС: жду отмашки — коммит и пуш делает руководитель.`

**Правила блока (жёсткие):** только названия; строка начинается с `[код]` или `[docs]`; запрещены пометки «(жду отмашки)», «TODO», пояснения в скобках и списки `- …` — всё служебное в `СТАТУС`/`ЗАМЕТКИ` **вне** блока; название — законченная строка `<код> <тип> <описание>` (типы — `10-git.md`), руководитель копирует её целиком. **Самопроверка:** строка, не начинающаяся с `[код]`/`[docs]`, удаляется. Порядок правок и пуш — `11-docs.md`.

## Коммуникация
Замечания/решения — в комментариях статьи с `→ <агент>`; в чат — короткий пинг («оставил замечания в S.NN»). Получив пинг, агент **обязан** открыть статью и прочитать комментарий. Дата записи — **фактическая** (`comment_stamp.py`); подробно — `11-docs.md`.

## Гейты (обязательны для всех)
1. **Ревью Лида** — до «Тестирую».
2. **БЖ-сверка Аналитиком** — если задача меняет правила/поведение (feature/refactor, правила дозирования/триажа/согласия/классов препаратов, правки «Бизнес-логика»/«Сценарии»): вердикт в секцию «Бизнес-логика (проверка Аналитика)» — «соответствует» / «внесены правки БЖ» / «есть замечания к реализации»; правил он не меняет. Сверка не нужна — РП помечает «БЖ-сверка: не нужна (причина)».
3. **Клиническая сверка (мед-проекты):** задача, меняющая правила лечения/дозирования, триаж, клинические шкалы, мед-тексты или мед-данные, **не уходит в «Готово» без вердикта медэксперта (Арсений)**: «клинически корректно» / «расхождение с источником X» / «требует куратора». Вердикт — в секцию «Клиническая сверка»; числа — только из источника (редакция + дата); спорное — пакетом куратору-врачу, не «по памяти».
4. **Безопасность (все проекты):** задачи, меняющие аутентификацию/права, ПДн, крипто или внешние интеграции, не стартуют без требований безопасности (Ной); PR проходит секреты/SCA/SAST и security-ревью; **релиз не закрывается, пока не обновлены модель угроз и поверхность атаки.** Находки — в реестр уязвимостей со SLA.
5. **`make ci` зелёный** — обязательный локальный прогон перед коммитом/PR.

## Статусы — инварианты
- **Канбан — единственный источник истины.** Двигает карточки **только РП** (скилл `status-briefing`), атомарно, сразу после отчёта агента. Агент колонки не двигает — только отчитывается.
- **Смена статуса — всегда 4 поля разом:** `status`, `awaiting`, `updated`, «Контекст передачи» + запись в канал (`comment_stamp.py`). Пустой `awaiting` у активного статуса (кроме `spec`/`planned`) — ошибка.
- Не дублируй статус в 4 местах: статус живёт в Канбане, остальное — зеркала.
- **Колонка «Деплой»:** РП двигает карточку в «Деплой» → DevOps выкатывает на тестовый контур (скилл `release`) и отчитывается в «Результат» → РП двигает в «Готово», приёмка — руководитель.
- «План спринтов» обновляет РП **один раз в конце дня**, одним проходом.
- Ревью: замечания по коду — **в PR** (inline/суммарно); в задачу — короткий вердикт («вернул на доработку, замечания в PR #N»). Подробности в задачу не дублируй.
- **Существенная доработка = новая задача** (не раздувай текущую). Эскалация: Дев/Тест → Лид → РП → Руководитель.
- **Перенос в другой спринт = НОВЫЙ код** целевого спринта + `carried_from`; перенос без нового номера — ошибка процесса. Чек-лист — скилл `status-briefing`.

## Docker
По завершении задачи **останови свой стек**: `docker compose down` (из своего клона; проект — из `.env`). RAM на машине критична — не держи контейнеры без надобности.
