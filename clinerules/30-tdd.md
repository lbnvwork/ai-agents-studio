# TDD и тесты

- Тесты пишутся ДО реализации (TDD): сначала скелет теста, затем код до зелёного.
- После реализации — повторно пересмотри тесты: какие кейсы ещё можно покрыть, что изменилось, какие устарели/неактуальны. Выводы отрази комментарием в статье задачи (секция «Тесты (TDD)»).
- Покрывай позитивные и негативные сценарии + security-сценарии (злоумышленник).
- **Docker: команды выполняй из своего клона — проект берётся из `.env` (`COMPOSE_PROJECT_NAME`), `-p` не нужен.** Явный `-p` — только чтобы адресовать чужой проект в этом каталоге (у студийных агентов стека нет). Имя проекта — в `.clinerules/00-role.md` или в `docker compose ls`.
- **Команды прогона — в скилле `run-tests`**, а не в правилах: у каждого проекта свой стек (в ядре пример веб-стека: на бэкенде `phpunit` + `phpstan`, на фронте `npm test` в контейнере).
- Стек не тот же? Положи вариант скилла в профиль: `profiles/<project>/skills/run-tests.<дорожка>.md` (или `run-tests.<код агента>.md`) — ядро при этом не меняется.
- Служебные команды, ждущие ввода, запрещены: `-T` для `exec`/`run`, `--no-pager` для git, `-y`/`--no-input` для пакетных менеджеров (в режиме терминала агента `Terminal Execution Mode = Background Exec` невидимая команда с ожиданием ввода повиснет молча).
- E2E — инструментом проекта (в ядре пример — Playwright; для мобильного приложения — Espresso/Appium), сценарии в `docs/05-Тестирование/Сценарии-E2E/`.
- Тесты зелёные — обязательное условие перед PR.
- CI (GitHub Actions) **работает**: при PR в `develop`/`main` запускаются джобы по стеку проекта (пример веб-стека: **Backend** — Composer install → миграции + `schema:validate` → test DB → PHPUnit → PHPStan → composer validate/audit; **Frontend** — npm ci → Vitest → build). Локальный прогон ОБЯЗАТЕЛЕН перед передачей на коммит/PR, команды — из скилла `run-tests`. Результат — обязательное поле отчёта и PR (напр. `phpunit OK (N tests)` · `phpstan analyse OK` · `npm test OK (N файлов / N тестов)`). «Пусть CI проверит» — не аргумент: CI лишь контрольная точка.
- **Линтеры и стиль — жёсткий режим (fail, без warn-режима).** Обязательный прогон — по стеку проекта (в ядре пример веб-стека: PHP CS Fixer `@PSR12+@Symfony`, PHPStan с расширениями, `composer-unused`, Deptrac; ESLint/Prettier/Stylelint, Knip). Любое замечание = красный прогон. Договорённость команды: **новый код пишется сразу чисто** — долг не копим (единоразовое приведение существующего кода делает Лид отдельной задачей).
- **Тесты не оправдывают код (мёртвый код).** Если символ (класс/метод/функция/экспорт) используется **только тестами** и нигде в прод-коде — это мёртвый код: удаляем символ, а тест переписываем под реальный сценарий. «Завели метод, чтобы было удобнее тестировать» — не причина тянуть его в прод. Проверка — скиллом `find-dead-code` **перед PR** (дев) и **на ревью** (лид).
