# TDD и тесты

- Тесты пишутся ДО реализации (TDD): сначала скелет теста, затем код до зелёного.
- После реализации — повторно пересмотри тесты: какие кейсы ещё можно покрыть, что изменилось, какие устарели/неактуальны. Выводы отрази комментарием в статье задачи (секция «Тесты (TDD)»).
- Покрывай позитивные и негативные сценарии + security-сценарии (злоумышленник).
- **Docker: всегда указывай проект явно.** У каждого агента свой стек (у РП в `{{PM_DIR}}` — `{{DOCKER_DEV}}` и `{{DOCKER_PROD}}`). Без `-p` compose целится в проект по имени каталога и отвечает «service … is not running» при работающих контейнерах. Имя проекта — в `.clinerules/00-role.md` или в `docker compose ls`.
- Бэкенд: `docker compose -p <проект> exec -T php sh -lc 'vendor/bin/phpunit'` (workdir `/var/www/html`, PHP 8.3).
- Фронтенд: `docker compose -p <проект> exec -T node sh -lc 'npm test'` (workdir `/app`, Node 20.20.2). Скрипт в `frontend/package.json` называется **`test`** (`vitest run`), есть ещё `test:watch`; **`test:unit` не существует**. Локальный прогон не работает: локальный Node 18.20.8 ломает vitest (`rolldown` требует `node:util.styleText` из Node ≥ 20.12) — фронт-тесты гоняются только в контейнере.
- Служебные команды, ждущие ввода, запрещены: `-T` для `exec`/`run`, `--no-pager` для git, `-y`/`--no-input` для пакетных менеджеров (в режиме терминала агента `Terminal Execution Mode = Background Exec` невидимая команда с ожиданием ввода повиснет молча).
- E2E — Playwright (сценарии в `docs/05-Тестирование/Сценарии-E2E/`).
- Тесты зелёные — обязательное условие перед PR.
- CI (GitHub Actions) **работает**: при PR в `develop`/`main` запускаются джобы **Backend** (Composer install → миграции + `schema:validate` → test DB → PHPUnit → PHPStan → composer validate/audit) и **Frontend** (npm ci → Vitest → build). Локальный прогон всё равно ОБЯЗАТЕЛЕН перед передачей на коммит/PR: `phpunit` + `phpstan analyse` (бэкенд) + `npm test` (фронтенд). Результат — обязательное поле отчёта и PR: `phpunit OK (N tests)` · `phpstan analyse OK` · `npm test OK (N файлов / N тестов)`. «Пусть CI проверит» — не аргумент: CI лишь контрольная точка.
- **Линтеры и стиль — жёсткий режим (fail, без warn-режима).** В обязательный прогон входят: **PHP CS Fixer** (`@PSR12 + @Symfony`, `--dry-run --diff`), PHPStan с расширениями (`strict-rules`, `deprecation-rules`, **`unused-public`**, `phpstan-doctrine`, `phpstan-phpunit`), `composer-unused`, **Deptrac** (границы контекстов по ADR); **ESLint** (flat + vue + sort-imports) / **Prettier** / **Stylelint**; **Knip** (неиспользуемые файлы/экспорты/зависимости фронта). Любое замечание = красный прогон. Договорённость команды: **новый код пишется сразу чисто** — долг не копим (единоразовое приведение существующего кода делает Лид отдельной задачей).
- **Тесты не оправдывают код (мёртвый код).** Если символ (класс/метод/функция/экспорт) используется **только тестами** и нигде в прод-коде — это мёртвый код: удаляем символ, а тест переписываем под реальный сценарий. «Завели метод, чтобы было удобнее тестировать» — не причина тянуть его в прод. Проверка — скиллом `find-dead-code` **перед PR** (дев) и **на ревью** (лид).
